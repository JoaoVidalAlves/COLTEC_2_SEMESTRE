QUESTÃO 4.1 - O QUE SÃO SUBCONSULTAS?
-------------------------------------

Uma subconsulta (ou "subquery") é uma consulta SQL escrita dentro de
outra consulta (a "consulta externa"), geralmente dentro de uma
cláusula WHERE, HAVING, FROM ou na lista de colunas do SELECT. Ela é
usada quando o resultado de uma consulta depende do resultado de
outra consulta menor, que é resolvida antes (ou junto) da consulta
principal. Subconsultas permitem expressar filtros, comparações e
cálculos que seriam difíceis ou impossíveis de escrever com um único
SELECT simples.

Subconsultas podem ser classificadas em dois tipos principais:

1) SUBCONSULTA NÃO CORRELACIONADA
   É uma subconsulta independente da consulta externa: ela pode ser
   executada sozinha, sem precisar de nenhuma informação vinda da
   consulta que a contém. O banco de dados normalmente a executa uma
   única vez, e o resultado é reaproveitado pela consulta externa.

   Exemplo (baseado nas tabelas do simulado):

       SELECT id, nome, categoria, preco
       FROM Produtos
       WHERE preco > (SELECT AVG(preco) FROM Produtos);

   Aqui, a subconsulta "SELECT AVG(preco) FROM Produtos" não depende
   de nenhuma linha da consulta externa - ela calcula a média geral
   uma única vez, e esse valor é usado para filtrar todos os produtos.

2) SUBCONSULTA CORRELACIONADA
   É uma subconsulta que depende de valores da consulta externa (ou
   seja, referencia uma coluna de uma tabela declarada fora dela).
   Por isso, ela não pode ser executada isoladamente: o banco de
   dados a reexecuta (conceitualmente) para cada linha considerada
   pela consulta externa.

   Exemplo (baseado nas tabelas do simulado):

       SELECT p.id, p.nome, p.categoria, p.preco
       FROM Produtos p
       WHERE p.preco > (
           SELECT AVG(p2.preco)
           FROM Produtos p2
           WHERE p2.categoria = p.categoria
       );

   Aqui, a subconsulta usa "p.categoria", que vem da tabela Produtos
   da consulta externa (alias p). Para cada produto p, a subconsulta
   recalcula a média de preço apenas dos produtos da MESMA categoria
   de p, por isso ela é correlacionada.

Resumo da diferença:
- Não correlacionada: independente, executada uma vez.
- Correlacionada: depende da linha externa, reavaliada por linha.
